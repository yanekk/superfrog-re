# bug-recorder — delivery report

## What was delivered

**You can now hand a bug to an agent by playing it, not describing it.**

- **Start Level** (Game menu) opens a window where you pick a level, lives (3, 5 or 7, default 3, as the game's own menu offers), points, energy, difficulty (Easy or Normal, the two the original's menu offers), Spud, Wings, and whether to record. It offers the 26 levels a real game reaches by its level code; the three spare copies of World 6 levels are left out because the original can't be started on them. A game started this way never unlocks "Continue from World N".
- **While recording**, a bar sits under the game picture (never over it) with a red dot, the recorded time and a STOP button. The clock counts only recorded play, so it stands still while paused. ⌘. and Game ▸ Stop Recording do the same as STOP.
- **STOP** opens a save window with the screenshot, where you are, the file name and a one-line note. Save writes one small file into the repo's `bugs/` folder (never committed) and puts its path on your clipboard for you to paste to an agent. If you had paused before pressing STOP, the game stays paused afterwards.
- **Anything that would change the game** while recording (Load State, Start Level, Reset, Continue, Import Disks, Play Level File, Quit) first asks: Save…, Discard or Cancel.
- **For agents:** tools that replay a recording without a window, play the same start and presses on the original game, say whether the two behave the same (and where they first differ if not), and turn a recording into a permanent test. When the original slows down and drifts off the recording, the tool now puts it back on track rather than giving up or wrongly saying "same" (task T14, added during the run with your yes).
- **A written guide for fixing a bug from a recording**, which a fresh agent finds from the project's start page.

**What happened to the black-screen bug:** your recording this morning went through the whole flow. It replays exactly to your screenshot and matches the original game all the way. The black screen did not appear this time, and the agent's own recordings (slot lost, won, gambled, jackpot), on today's version and on the earlier one, never showed it either. Each time there are about 2 seconds of black after the slot machine, then the map, exactly as the original does. So the bug is not fixed, because it was never caught; it may need something specific in how you played that day.

**Not delivered:** no fix for the black screen, since it could not be reproduced. Hard difficulty is not in the dialog (your call).

## Risks and follow-ups

- **The black screen is still unexplained.** It may depend on how you played, or come from the old app's display rather than the game itself, which the checks couldn't cover.
- **A small jackpot difference:** on one jackpot, our game counts the score up on screen slightly differently from the original. Both end with the same score. Logged, not fixed.
- **The "show me exactly where they differ" mode** of the comparison flags a harmless start-up leftover in its very first frame, so for now it doesn't point at real differences. The guide leans on it; worth fixing next.
- **Comparisons can miss a difference made during a slowdown**, because the tool re-aligns the two games after each one. The tool prints how often it did that, so a reader can see it.
- **Easy mode has no reference tests yet.** A difference found on Easy may be the first time anyone looked; the guide says so.
- **Some tests are unreliable:** one test of the timeout safety net fails now and then (it did before this plan too); two fullscreen tests fail on this display before and after this plan; the real-window dialog tests lose a keypress about one run in four when other app windows are on screen.
- **A bug-fix run started with `@repo/single`** only runs the Python tests on its own; the guide tells the agent which engine tests to run, but nothing enforces it.
- **Small leftovers:** a note pasted with Windows line breaks gets two spaces per break; replaying in widescreen never matches the 4:3 screenshot; a game started from the dialog keeps not saving progress through a new game begun after its game over, until Reset or Continue; the menu test's list of File and View items is out of date.
- **Two possible engine differences seen in passing at the start**, unrelated to recording (a sound on Easy W1-1, a frog position on the bonus level). Logged for a later look.
