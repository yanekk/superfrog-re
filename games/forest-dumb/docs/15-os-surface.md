# 15 — The OS surface

Everything `FOREST_DUMB_FOREVER` asks of the Amiga's OS, measured on the original (oracle,
2026-11-11), so the translated program's machine answers exactly this and runs no Kickstart code
(plan `forest-dumb-translator`, DESIGN §2.8, T01; T26 builds the answers). The data is
[`re/os-calls.toml`](../re/os-calls.toml), regenerated by:

```
cd games/forest-dumb/engine && cargo run --release -p fd-conform -- os-surface [--frames 300] [--worlds 1,2]
```

about 25 s. The full test `fd-conform/tests/os_surface.rs` reruns it and fails when the committed
file differs, so the file is current for the program, the emulator build and the tool.

## How it was measured

Two runs on the oracle. World 1: power-on with `boot-to-level1` (the crack, disk 2's prompt, the
title, Start, level 1's load, SCENA 1) and 300 frames of play, with L held for frames 10 to 19 of play
so the program's keyboard handler runs. World 2: from the title at frame 4990, with the immediate of
`title_code_world`'s `move.l #$0, world_index` (`h0+$778c`, the branch taken when no code was entered)
set to 1 until it has run, so `load_world` loads world 2 on the program's own path. `world_index`
itself cannot be poked: `title_code_world` writes it in the same step `load_world` runs.

Every even address of the five hunks and every slot of every jump table in ExecBase's library, device
and resource lists is counted (`Amiga::watch_pcs`). A `jsr`/`jmp` through a negative displacement off
an address register is a library call; its library is the one whose slot at that offset ran at least
as often as the site in every step, tied where needed by the library base the program stored in its
own variable (the file routines call through `a5` loaded from `h0+$908e`, and exec's own slots at
-30 and -36 run more often than `Open` and `Close`). Executed instructions are decoded (each length
agrees with Moira's disassembler: no `[undecoded]` section) for absolute OS addresses, CIA registers
and other exits, and pointers the OS hands over are followed along each straight line of code.

Phases (`when`): **load** where `system_on`, `system_off` or a file routine ran, or the OS holds the
machine between them; **title** where `title_pass` ran; **play** where `game_frame` ran; **other** for
the rest (start-up before the first load, the prompts, SCENA). Counts add up both runs.

## Library calls, and what the program relies on

No result is checked except `Open`'s; nothing else is null-tested, so every answer must be a usable
value.

| Call | Sites | Arguments | The program relies on |
|---|---|---|---|
| exec `OldOpenLibrary` (-408) | `entry` `h0+$82`; `load_file`, `load_file_raw`, `read_marker` (`h0+$8ed0`, `$8f64`, `$8fe4`) | `a1` = `"graphics.library"` (`h0+$1e10`) at entry, `"dos.library"` (`h0+$9092`) in the file routines | `d0`, the library base: graphics' is read (below) and used as `a6`; dos's is stored at `h0+$908e` and is `a5` for `Open`, `Read`, `Close` |
| graphics `OpenFont` (-72) | `h0+$a2` | `a0` = TextAttr `h0+$1e40`: `topaz.font`, 8 | `d0`, a TextFont: `+$22` (`tf_CharData`, long) and `+$26` (`tf_Modulo`, word) are copied to `h0+$1e54` and `h0+$1e58`, which nothing reads afterwards. Any readable pointer will do |
| graphics `CloseFont` (-78) | `h0+$b8` | `a1` = that font | nothing |
| graphics `FreeSprite` (-414) | `h0+$be` | `d0` = whatever `CloseFont` left | nothing. Meant as exec `CloseLibrary` (`a1` is GfxBase), but `a6` still holds GfxBase; graphics.library is never closed |
| dos `Open` (-30) | `h0+$8eec`, `$8f80`, `$9000` | `d1` = `load_name` (`h0+$90a2`) or `"df0:!EAGLE_SOFT!"` (`h0+$9113`); `d2` = `$3ed` (MODE_OLDFILE) | `d0`: zero sends `load_file`/`load_file_raw` to the insert-disk prompt and `read_marker` to `prompt_disk_2`, then retries; nonzero is stored at `h0+$909e` as the handle |
| dos `Read` (-42) | `h0+$8f1e`, `$8fb2`, `$9032` | `d1` = handle; `d2` = `load_buffer` (`h0+$437c8`), `load_target` (`h0+$9086`) or `h3+$398`; `d3` = `$6ffff` | the bytes in the buffer, and `d0`, stored at `h0+$908a`: the length `h0+$9060` copies from `load_buffer` to `load_target` for a file without `ESL!`. A `-1` is not checked |
| dos `Close` (-36) | `h0+$8f2e`, `$8fc2`, `$9042` | `d1` = handle | nothing |
| exec `CloseLibrary` (-414) | `h0+$8f3e`, `$8fd2`, `$9052` | `a1` = dos's base | nothing |

31 files are opened over the two runs (31 `Open`, `Read`, `Close`, 32 `OldOpenLibrary`).
`save_scores_unreferenced` (`h0+$92d8`, dos `Write` at `h0+$9488`) never runs, as docs/07 found.

## OS memory read and written

| What | Sites | Why |
|---|---|---|
| `$4` ExecBase, read | `h0+$76`, `$8ec4`, `$8f32`, `$8f58`, `$8fc6`, `$8fd8`, `$9046` | only as `a6` for the exec calls above; nothing in ExecBase is read |
| GfxBase `+$26` (`copinit`), `+$32` (`LOFlist`), read | `h0+$88`, `h0+$90` | saved at `h0+$1e32`, `$1e36` for `quit_to_dos`, which puts them back in COP1LC/COP2LC (not run) |
| `$6c` level 3, `$68` level 2 autovectors, read | `h0+$f8`, `$118`; `system_off` `h0+$476` (`$68` only) | the OS's handlers, saved at `h0+$1e26`, `$1e2e` |
| the same, written | entry `h0+$100`, `$120`; `system_on` `h0+$3fa`, `$400`; `system_off` `h0+$45e`, `$47e` | the program's `level3_handler`/`level2_handler` in, the OS's back for a load |

## Interrupts and who owns them

| Level | Load and other | Title | Play |
|---|---|---|---|
| 1 (disk, soft) | OS | none taken | none taken |
| 2 (CIA-A) | OS | none taken; vector is the program's | program (`level2_handler`), on a key |
| 3 (vblank, copper) | OS | none taken; vector is the program's | program (`level3_handler`), once a frame |
| 6 (CIA-B) | OS | none taken | none taken |

Levels 4, 5 and 7 are never taken and their vectors stay the OS's. The title takes no interrupt at
all: `load_list_title` ends in `system_off` (INTENA `$c018`, the program's vectors), and the title's
copper list raises no copper interrupt, which is why `irq_count` stands still there.

What `system_on` hands over: COP1LC `h1+$0` and COPJMP1, INTENA and DMACON off, the saved `$6c`/`$68`,
CIA-A ICR `$97`, then the saved DMACON, ADKCON and INTENA (`h0+$1e3c`, `$1e3e`, `$1e3a`, read at entry)
with their set bit. What `system_off` takes back: INTENA and DMACON off, DMACON `$87f0`,
`level3_handler`, CIA-A ICR `$7f` then `$88` (serial port only), `level2_handler`, INTREQ clear, INTENA
`$c018`. The machine never has to run an OS interrupt in the title or in play.

## CIA registers

| Register | Access | Sites | Use |
|---|---|---|---|
| `ciaa_pra` | read | `h0+$70c8`, `$7b96`, `$7c7e` (polled loops) | fire, bit 7: title, prompts, SCENA |
| `ciaa_pra` | modify | `h4+$184d2` | the player sets bit 1 (the filter/LED) |
| `ciaa_icr` | write | `h0+$108`, `$110`, `$406`, `$466`, `$46e` | entry and `system_off` (`$7f`, `$88`), `system_on` (`$97`) |
| `ciaa_icr` | read | `h0+$1f98` | `level2_handler`: serial port flag |
| `ciaa_sdr` | read, write | `h0+$1fa2`, `h0+$1fb4` | the key byte into `last_key_byte`, then cleared |
| `ciaa_cra` | modify | `h0+$1fac`, `$1fd0` | the keyboard handshake (bit 6 set, then cleared) |
| `ciab_prb` | modify | `h0+$51a`, `$522`, `$52a` | after each load list: motor off and df0 selected then deselected, latching the motor off |

## Not seen

The run cannot see OS code reached by a return rather than a `jsr`/`jmp`, a pointer kept anywhere but
a register or an absolute variable, or paths it does not take: game over, the end screen, worlds 3 to
6, a failed open, keys other than L in play (Esc, HELP and P go through the same `level2_handler`). No
`jsr`/`jmp` leaves the hunks except the library calls above (no `[[jump]]` section).
